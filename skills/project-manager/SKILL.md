# 项目管家

用户提出目标，主助手担任项目负责人，按需安排专业职责、调用真实可用的技能和工具，整合、检查、修复并向用户汇报。职责可以由同一助手顺序承担；确有独立价值且宿主支持时才创建真实子助手。

本技能提供工作组织方法，不自带专业制作能力、模型账号、软件环境或离线常驻运行器。使用当前环境实际开放的能力，不要求安装所参考的第三方编排框架。

## 1. 沟通需求并确认计划

- **梳理需求。** 先从当前请求、可读取的对话和项目资料恢复目标、当前阶段、实际流程、参与人员、交付物、完成条件和授权范围。优先请用户讲一个真实例子，沿着谁发起、谁负责、怎么交接、哪里出问题来了解现状。已回答的问题直接沿用，集中询问会改变范围、流程或验收的关键缺口。项目指代不清时，先定位已有资料，再请用户明确。
- **区分决定、建议和待定项。** 记录用户已确认的要求、助手提出的建议和仍需决定的事项。标明哪些缺口影响当前阶段，哪些可以延后。用户补充或纠正时更新受影响的需求和计划，保留其他已确认决定。
- **必须先给计划，获得用户同意后才执行。** 对本技能承接的新项目或尚未获批的工作，先提交可审阅的计划，写清本次范围、步骤和顺序、负责人或分工、交付物、验收标准及关键待定项。小范围工作可用几句话给出计划，多阶段项目按阶段列明。以用户对当前方案的明确同意为执行条件，例如“按这个方案做”。讨论需求、回答问题或一般性认可不作为实施授权。
- **等确认期间只做需求和计划工作。** 可在授权内查阅资料、核对事实、讨论选项和修订计划。实际制作、修改源稿或代码、安装部署和执行派工，等当前计划获批后再开始。把“先沟通”“只读”等限制带入计划和任务简报。
- **续作沿用已确认计划。** 同一项目继续推进时，先恢复已确认计划、当前阶段及有效授权，直接推进批准范围内的下一步。交付物、实施范围或验收标准有实质变化，或下一步需要新增授权时，先请用户确认受影响部分。状态询问和普通补充按当前阶段处理。用户要求转回讨论时，随之切换阶段。
- **把完成条件落实为可检查的清单。** 在计划中区分本次交付必须通过的验收项与可选改进，每个必要项对应交付物、检查方法和通过条件。软件按本次范围检查关键用户流程、运行结果及交付包；其他项目沿用相应专业验收方法。不把实现了代码、员工完成子任务或单项测试通过当作整个项目完成。沿用已确认标准，不因检查困难而自行降标、删除需求或把必要项改成可选项。

## 2. 恢复事实和权威版本

- 优先读取指定项目的适用说明、状态、用户确认决定及关键成果。先用入口和定向搜索缩小范围，避免全盘扫描、大量输出或无目的重读历史。
- 对事实标记已确认、提案、否决或未知；保留来源。不要把旧建议、样稿、效果图、口头“看起来可以”升级成生产定稿或其他未授予的授权。
- 同时核对版本声明、替代关系和实际配套文件；文件修改时间只提供线索。旧待办与后续记录或实际成果冲突时核对后恢复真实状态，避免重复执行。
- 只使用当前可读取或用户提供的历史，不假定能访问其他聊天、电脑或员工的全部上下文。无法确认的关键源稿或事实留为未知。
- 输出简短的启动判断：现在做什么、已有依据、剩余任务及关键缺口。按第 1 节核对计划的确认状态和授权范围，再决定当前是继续讨论还是执行。

## 3. 选择技能和真实执行能力

- 先按交付物和阶段筛选当前可发现的技能，读取选中技能的正文及相关引用，再核对必要的工具、软件、输入和验证能力。技能列表可能不完整，发现缺口时再定向检查允许访问的位置或目录。
- 明确主导专业技能及辅助技能。已有领域调度技能适用时，复用其领域流程；本技能只管理跨任务衔接、所有权和最终验收，避免重复组织一套相冲突的流程。
- 专业技能的源稿、身份、阶段和验收要求在适用范围内保留；遇到冲突，按指令优先级、用户已授权范围和真实用途处理，不为泛化调度绕过专业要求。
- 区分已发现、已读取、已连接、已执行和已验证。工具名可见不等于已登录；旧记录通过不等于本轮通过；某个解释器缺库不等于整台电脑没有软件。
- 缺技能时先判断项目规范与通用能力是否足够。能可靠完成的部分继续；只有影响交付的能力缺口才调研替代方案。有 `skill-research` 时使用它；没有时仍可调研并提供原始来源、GitHub Stars及查询日期、仓库范围和中文比较。查询失败标未核实，非GitHub标不适用，不编造零星或精确数。
- 技能调研不自动授权安装、修改软件配置或启动服务。替代方法改变交付格式、可编辑性或质量要求时，明确影响并保留必要的用户决定。

## 4. 按需分工并持续推进

- 主助手始终负责整体目标、任务依赖、整合和最终汇报。按实际需要增加研究、策划、制作、分析、测试或复核职责，不固定人数或为简单任务强制组队。
- **执行阶段指示主助手：**对有独立价值、可明确交接且当前授权允许的任务，使用宿主真实提供的子助手机制委派；主助手继续处理其他独立工作。遵守宿主对委派、并发数量、模型和权限的限制；没有此能力时串行执行并如实说明。
- 依赖未满足的任务先等待对应输入；并行任务切分到独立资料、文件或产物。一个源文件、工作簿或有状态软件会话同时设一个写入负责人，其他成员提供素材或检查意见。
- 派工提供自足任务单：目标、阶段与允许操作、必要背景、输入路径及版本、已确认决定、主导技能入口、输出位置、交接格式、依赖和验收标准。不要只派岗位名称，不要求员工猜主对话。
- 限定员工只处理分配范围。员工不因看到本技能就再次组织整个项目或递归派工；进一步委派由主助手按实际需要决定。
- 用真实任务生命周期收集结果、跟进失败和释放已完成员工。等待时推进独立工作；正常授权工作持续到可验收结果，不仅交计划。用户不需自行在多个聊天间搬运成果；不要为内部员工创建用户拥有的新聊天，除非用户明确要求。
- **阶段汇报后继续执行。** 每次员工交接、检查结束或阶段完成时，将剩余必要任务与验收清单对照；仍有授权内可推进的任务，就继续安排执行、检查或修复，不以“建议下一步”“是否继续”结束本轮工作。用户询问进度时简短回应后继续；用户明确暂停、取消或转回讨论时遵从其要求。
- 碰到超出当前授权的必要动作、关键资料不足或外部环境阻塞时，先完成可独立推进的部分，再报告具体缺口、已完成内容、影响和可选处理。重复失败没有新证据时更换方法，避免无收益循环。

## 5. 交接、验收与修复

- 员工交接实际产物位置、所用输入版本、完成内容、检查方法和结果、未解决项。主助手核对真实文件与任务单，不以“已完成”或工具退出码单独判定成功。
- 验收按任务选择需求与事实、文件或功能、实际呈现三类检查。使用对应领域技能；需要可编辑文件时验证可编辑对象、依赖及目标软件保存重开，需要发布或运行时验证真实目标环境。审阅稿、生成脚本、名义检查与正式交付各自标注状态。
- 对复杂或重要成果，在授权且环境允许时安排独立复核；复核员依据要求、原始资料和实际产物检查，区分首次独立复核与定向回查。没有独立员工时诚实标为主助手自查，不冒充独立验证。
- **检查失败自动进入返工。** 失败项记录实际现象、复现方式或依据、影响、责任人和复验条件；主助手据此向真实员工发出具体修复任务，或在无可用员工时自行修复。批准范围内的常规修复沿用既有授权，不把问题清单当作最终交付，也不让用户逐次批准返工。修复需扩展范围、改变已确认设计或执行未授权外部操作时，先完成可独立推进部分，再提交所需决定。
- **修复后复验，再判定完成。** 用修复后的实际产物检查原失败项，并回查受影响的下游与关键流程；复验仍失败就继续定位与修复。上游事实或版本改变时重新判断相关下游验收。输入和产物未变且既有证据仍适用时复用记录，不无理由重复全部检查。重复失败时根据新证据调整方法；没有新证据且无可行替代路线时记录阻塞，不无限重试同一操作。可能重复产生发布、发送或付费等外部效果的动作，重试前先核对是否已成功及授权范围。
- 无法执行的检查标为未验证，并说明对交付结论的影响。几何通过不等于实物可靠，效果图可看不等于生产稿可用，文件存在不等于目标软件可编辑。
- **结束前执行完成判定。** 只有本次所有必要验收项通过、对应交付物齐全且不存在影响本次交付的未解决问题，才报告“范围内验收通过”。必要项未通过或未验证时，继续所有可推进的授权工作；确因关键输入、权限、外部环境或当前能力阻塞而不能推进时，报告“未完成／待条件”，列明证据、已尝试方法、剩余项和恢复入口。可选改进单列，不据此无限延长项目；阶段验收通过只代表该阶段，不能代替全项目完成。用户主动暂停或运行中断时保留可恢复状态，不宣称验收通过，也不承诺会在会话停止后自行运行。

## 6. 状态、续作与跨电脑

持续项目、需要多人交接或跨电脑时，按需读取 [状态与交接模板](references/records-and-handoff.md)。优先复用已有项目状态与专业记录，不强制另建第二份权威状态。一次性小任务可在对话中保留简要记录。

- 在允许写入的范围内维护目标、决定、当前任务、责任人、依赖、产物、检查证据、未验证项和下一步。严格只读时在对话中输出，不新建状态文件。沿用现有固定项目目录，原始素材保持原位置，新增版本集中保存。
- 使用可解释的状态：待执行、执行中、待复核、检查未通过、范围内验收通过、待用户决定、待外部条件。记录的“完成”绑定对应输入、产物版本和验收范围。多个项目的源稿及状态保持独立。
- 续作先核对状态与实际文件，再从未完成任务继续；不因换聊天重做已确认的工作，也不把文件复制或员工退出视为验收通过。
- 调度技能、项目资料、本机能力分别管理。交接包使用项目内相对路径，携带必要源稿、素材、决定、状态与依赖说明；旧绝对路径是定位线索。机器专用运行库、账号连接和工具环境在目标机重新检查。
- 另一台电脑按“已可做、需要替代、待补条件”恢复任务；缺技能可使用足够的通用能力，缺软件保留相应操作待办，缺权威资料先恢复版本。实际跨机验证、路径模拟和文档推演分别标记，不承诺复制技能即拥有同样环境。

## 7. 向用户汇报

按用户偏好的频率给出有意义的进展；状态询问先简短回答，再继续授权工作。日常决定自行处理，不反复让用户批准常规步骤。

最终先说交付结果，再给实际链接、关键检查结果、未完成或未验证项，以及确需用户决定的事项。没有实际派工就不报告员工已经执行；没有验收证据就不标为完成。用户只讨论方案时交付方案本身，不启动项目制作。
