# 状态与交接模板

用于持续项目、多员工任务或跨电脑续作。模板按实际复杂度裁剪；复用项目已有 `project-state.json`、项目说明、工作记录或领域主线文件，不要求它们改名或重构。一个明确入口指向当前有效状态，其他记录只提供依据。

## 启动简报

```text
项目与位置：
本次目标和交付物：
当前阶段、允许操作及明确限制：
已确认决定及来源：
提案、否决或未知事项：
权威输入及版本；已被替代的版本：
已完成产物及有效验收证据：
待完成任务与依赖：
当前可用技能/工具；待核对能力：
拟议分工、整合负责人和验收办法：
```

新请求已足够明确时，简报可以缩为几句话后直接执行；不要要求用户重复确认既有决定。

## 员工任务单与交接

```text
任务标识与职责：
项目根目录及本任务目标：
阶段、允许的读写范围和明确限制：
输入文件、版本与必要背景：
必须遵循的已确认决定：
主导技能及可读取入口；相关工具能力：
输出位置和交付格式：
前置依赖与本任务的唯一写入对象：
验收标准和所需证据：
返回：完成内容、实际产物、检查方法及结果、问题与影响。
只处理本任务；需要跨范围修改或进一步委派时交回主助手协调。
```

只读角色约定是任务范围，不证明平台提供独立只读沙箱。能力和权限以当前宿主实际配置为准。不要把账号登录信息或无关的整段对话塞入员工简报。

## 项目状态最小内容

沿用现有数据结构，确保这些信息可找到：

| 信息 | 用途 |
| --- | --- |
| 目标、阶段与有效范围 | 确认本次可以推进到哪里 |
| 当前源稿与替代关系 | 避免旧版和新配套文件混用 |
| 确认决定、未知与依据 | 避免把提案升级成事实 |
| 任务、负责人、前置依赖和状态 | 组织顺序、并行与文件所有权 |
| 实际产物及输入版本 | 判断交接和验收是否对应同一份工作 |
| 检查方法、证据、范围与未验证项 | 使通过结论可追溯 |
| 阻塞、必要决定与下一步 | 支持续作和汇报 |

保存检查时，可用哈希、明确版本或其他可靠方法绑定输入和产物。记录工具成功、结构检查、视觉检查、原生软件检查等实际做过的范围，不需要为每个小任务强制计算全部哈希。

## 跨电脑交接

交接至少包括：

1. 当前目标、阶段、允许操作及确认决定。
2. 权威源稿、最新成果和需要的项目素材；必要时记录原件引用位置。
3. 当前任务、依赖、已通过检查、待验证及下一步。
4. 本次使用的技能名称或可携带副本及版本、必要工具、字体和其他运行依赖说明。
5. 项目内相对路径；目标机对本地路径、软件和连接的实际映射。

调度技能可单独迁移；专业技能或工具若未携带、未安装或不可用，明确列为能力缺口。项目文件齐全不代表专用软件、账号或运行环境已恢复。目标机按其实际支持的技能发现路径部署，不写死某一台电脑的磁盘或用户名。

目标机能力检查用下表即可：

| 需要的能力 | 实际发现与验证程度 | 可继续的工作 | 缺口及影响 | 下一步 |
| --- | --- | --- | --- | --- |
| 读取输入与预览 | 待核对 | 待判断 | 待判断 | 定向检查 |
| 专业技能与制作工具 | 待核对 | 待判断 | 待判断 | 选择可用路线 |
| 原生文件或目标运行环境验收 | 待核对 | 待判断 | 待判断 | 保留验收范围 |

## 判定边界的例子

- 旧日志写“重试”，后续成功记录及产物齐全：核对版本和结果，恢复真实状态，不盲目重跑。
- 状态指向新版，但目录有大量旧文件：沿替代关系选择整套配套输入，不只挑日期最新的单个文件。
- 有效果图与参考SVG，生产规格和原生验收未完成：交付审阅结果，保留生产任务。
- 几何及动画检查通过，材料和实物试验未做：分别记录技术检查通过与实物待验证。
- 当前解释器缺库：检查可用替代环境或工具，不把局部缺库扩大成整机能力缺失。

这些是判定方法，不是固定项目事实或必须复用的领域流程。
