# 换电脑与能力缺口

`project-manager` 将技能指令、项目资料和本机环境分别管理。当前只做过本机迁移条件检查与路径映射推演，尚未在第二台电脑实跑。

## 交接时带什么

- 调度技能的三个运行文件及版本；实际用到的专业技能名称与版本或合法可携带的副本。
- 权威源稿、最新成果、必要素材及清楚的版本替代关系。
- 当前目标、任务阶段、允许操作、已确认决定、未完成项与下一步。
- 验收证据和未验证项；软件、字体、运行库及连接依赖说明。
- 项目内相对路径，以及不能随包携带的外部素材位置说明。

不要把密钥、账号令牌或无关聊天记录放进公开交接包。它们应由目标环境按需要单独配置。

## 到新电脑先检查什么

| 能力 | 缺失时如何继续 | 不能直接宣称 |
| --- | --- | --- |
| 权威输入和项目状态 | 定位有效资料，无法确认的事实标未知 | 已找回完整上下文 |
| 调度技能 | 按目标宿主规则加载并确认可读 | 技能名出现即安装成功 |
| 专业技能 | 先评估项目规范和通用方法；不足再调研 | 部分提示词等于完整专业技能 |
| 子助手机制 | 由同一助手依次承担职责并如实汇报 | 已进行了真实多人独立复核 |
| 目标软件或运行库 | 先做状态、结构等可验证部分，保留原生验收 | 文件存在即能编辑保存 |
| 字体、素材或连接 | 说明替代影响或待补条件 | 预览可读即制作环境齐全 |

不要把旧机器的绝对路径当成新机器路径。先映射项目目录，再逐项检查真实依赖。某个解释器缺库，也不代表目标电脑完全没有可用环境。

## 如何汇报

分别列出“已可做、需要替代、待补条件”，每项附实际发现、交付影响和下一步。安装、配置修改或外部发布按当前用户授权处理。

当未来完成真正跨电脑运行时，再记录目标环境、执行范围、输入版本和结果，并更新验证说明；当前不能提前写成兼容性承诺。
